# 资产预览

Dozer 的一个核心设计原则是:**你应该尽量通过 AI 去修改产物,而不是自己直接改。** 所以预览面板默认是"渲染/查看"优先,不是"编辑器"优先——它首先要让你不用跳出 Dozer 就能看懂 agent 刚刚交付了什么。

## 怎么打开

从文件树、项目面板的链接、验收视图的改动文件列表等各处点一个文件,都会在预览面板(左二区域)开一个新标签。

## 两条渲染路径

Dozer 根据文件扩展名自动选择用哪种方式显示,你不需要手动切换:

- **原生只读代码编辑器**——覆盖常见文本类扩展名(`rs/toml/md/txt/json/yaml/yml/sh/py/js/ts/tsx/jsx/html/css/xml/log/conf`,以及按文件名匹配的 `.gitignore`)。这是直接画在 iced 界面里的原生控件,不是网页。默认**只读**;右键菜单里有一个"编辑"选项可以打开一个可编辑的浮层——这是刻意的默认值,不是疏漏:预览首先是给你"看"的,只有你明确点了"编辑"才进入可改状态。
- **Flyfish webview**——一个内嵌的、自托管的离线预览组件(`wry` 真实原生子视图,不是 iced 画的),覆盖图片、PDF,以及 Markdown/Office 等长尾格式渲染。`.md`/`.markdown` 默认也走这条路径(渲染成 GitHub 风格的排版,而不是给你看原始文本),右键"编辑"同样能切回原生编辑器改源文本。`.html`/`.htm` 直接以真实 `file://` URL 加载,相对路径的 CSS/JS/图片都能正常解析,适合本地跑起来的网页类产物做验收现场。

Flyfish 只会渲染你已经明确打开过的文件(白名单机制),不会把整个项目目录暴露成一个网站。

## 网页预览

预览面板本身也能开网页标签,带一个极简地址栏——主要用途是本地跑起来的 Web 项目(`localhost:xxxx`)的验收现场,也能看外部链接(文档、GitHub)。这**不是**一个功能完整的浏览器,没有历史记录、书签、多标签管理那一套(那些在 [Web/浏览器面板](panels.md#web浏览器) 里,是另一个东西)。这里的定位很单纯:不想让你为了看一眼产物就跳出 Dozer。

## 关于"编辑"入口

按项目的关键裁决,预览类功能默认只做渲染/查看,直接编辑入口不是白给的——右键"编辑"这条路径存在,是因为总有极少数场景(比如临时手改一个配置值、给 agent 报错前先自己确认一下)绕不开你亲自动手。但正常工作流应该是:看到问题 → 回终端跟 agent 说 → 让 agent 改 → 再来预览看结果,而不是习惯性地自己在预览里改完就算数。
