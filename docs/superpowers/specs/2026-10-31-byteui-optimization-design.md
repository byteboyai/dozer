# ByteUI 跨产品优化设计

日期：2026-10-31。状态：P0/P1/P4/P5/P6/P7 主要代码与自动化测试已实施；P2 生产调用已迁移到显式窗口 API；P3 的跨仓重复依赖已通过升级到 Dozer `libs-2026-10-30a` 解除，最终 locked 编译待 ByteUI 新 tag。

实施计划：[plan](../plans/2026-10-31-byteui-optimization.md)。本文记录当前源码分析后的目标设计，不代表功能已完成或性能收益已测得。

## 1. 背景与事实基线

ByteUI 已是独立的 iced 0.14 组件库，当前版本为 0.5.0。复用关系包括：

1. Dozer / Digger 直接消费 ByteUI 组件与 token。
2. 两产品经 ByteHost 的 chrome、settings-ui 消费 ByteUI。
3. Digger 经 Dozer 共享面板库间接消费 ByteUI。

本设计涉及四个仓库：`byteui`、`bytehost`、`dozer`、`digger`。相对路径以这些仓库的共同父目录为基准。

| 源码证据 | 当前结论 |
| --- | --- |
| `byteui/src/theme/icon_size.rs` | `set_scale` 未拒绝 NaN；环境变量正数未统一钳制；未初始化运行时值时 accessor 会再次查询环境变量 |
| `byteui/src/native_menu.rs` | 单个线程局部裸指针记录菜单窗口，借用被提升为 static；窗口生命期未在类型/API 中表达 |
| `dozer/crates/dozer-app/src/platform/*_overlay.rs` | 多个浮窗打开时切换菜单宿主、关闭时恢复主窗口，产品代码承担全局状态维护 |
| `byteui/src/theme/color.rs` | token 与方案名称分开存储；任意 `set_theme` 与命名方案的关系未形成完整契约 |
| `byteui/src/feedback/math_curve.rs` | 动画连续请求重绘；每帧创建 481 点底路径及粒子路径，尚无本次实测数据 |
| `dozer/crates/dozer-app/src/theme/region.rs`、`byteui/src/theme/region.rs` | 共享外壳仍有重复来源；Dozer 已有一致性检查 CI |
| 两产品 Cargo 配置与 workflows | 本地存在 path patch；Dozer 比对用 ByteUI checkout 未固定 ref；Digger check 未使用 locked |

`2026-10-16-byteui-remaining.md` 为历史快照，其中版本号、菜单/页签迁移与 CI 描述不再作为当前事实依据。此前“region 全部留在应用”的拆库约定在本设计覆盖范围内修订为：共享外壳归 ByteUI，产品面板归应用。

## 2. 目标与非目标

目标：保证缩放合法、菜单归属明确、发布组合可复现；减少外壳配置重复；降低动画无效工作；建立跨原生 UI 与第一方网页的主题一致性契约。

非目标：升级 iced；拆分跨框架 token crate；重写面板状态机；替换全部 RwLock；统一产品业务布局；修改第三方网页主题；引入 JSON 驱动 UI。普通控件的锁与分配优化须有测量证据，不预设为瓶颈。

## 3. 设计决策

### 3.1 缩放入口与运行时值

所有入口共用纯函数校验：非有限数、零、负数无效；有限正数钳制到 `[SCALE_MIN, SCALE_MAX]`，当前为 `[0.5, 3.0]`。

- 环境变量优先级保持 `BYTEUI_ICON_SCALE` > `DOZER_ICON_SCALE` > 持久化 > token 默认值。主变量非法时允许回退旧变量。
- `set_scale` 的无效输入忽略，保留原有效值；`zoom_by` 拒绝非有限或非正乘数，乘法溢出也不写入状态。
- `init_scale` 完成一次解析并物化运行时值；初始化后的 accessor 不再逐次读取环境变量。未初始化的旧调用路径保持可用。
- `reset_scale` 恢复本次启动的有效环境覆盖或 token 基准；落盘保留现有“恢复出厂基准”的语义。明确 token 后续替换是否影响基准，并用测试锁定，不能意外冻结原有运行时换主题能力。
- 合法缩放路径维持现有 API；不改变持久化文件格式与旧变量兼容性。

### 3.2 菜单显式归属与生命周期

目标接口为显式窗口上下文的 `show_for_window`（名称为设计名）。窗口上下文由 ByteHost 平台层/产品窗口集成层提供，ByteUI 不依赖 ByteHost。

- ByteUI 负责菜单描述、AppKit 渲染与同步选择结果；宿主负责窗口身份、存活期及坐标来源。
- 优先采用调用期间借用存活窗口句柄、在主线程解析 NSView 的方案，不向调用者返回 static 引用。
- iced 消费方需在现有 `window::run` 或等效的主线程回调里调用，回调结果再映射为产品消息；直接 winit 宿主可在事件处理中借用窗口。实施前核对返回消息约束，不能用丢弃选择结果来换取可编译。
- 如必须使用注册表，条目必须带窗口身份/代次，销毁时移除，迟到请求返回无选择；禁止复用已关闭窗口的身份。
- 每次执行校验主线程、窗口有效性和坐标归属；无可用窗口时返回可识别的无选择结果，不能回退到另一个窗口。
- 迁移保留旧入口的短期适配，全部生产调用迁移后删除全局指针及开关浮窗时的恢复接线。不能只标记 deprecated 而保留悬空引用实现作为最终状态。

这是潜在生命期风险的治理；当前审计未复现实际崩溃。

### 3.3 两种依赖验证

**发布组合**：全新 checkout、不携带本地 patch，使用固定 tag 与 lockfile，`cargo check --locked --workspace --all-targets`。Dozer、Digger 及 ByteHost 的 ByteUI 声明通过守卫对齐，Dozer 的声明上收至 workspace。

**候选组合**：临时配置将候选 ByteUI 精确 SHA patch 进选定的 ByteHost、Dozer、Digger 消费图；记录所有仓库 SHA，更新临时锁文件后以 locked 构建。候选包含 ByteHost 或 Dozer 改动时一并覆盖，不能拿发布版宿主验证尚未发布的接口。

ByteUI CI/可复用 workflow 提供候选组合入口；现有产品 CI 保留发布组合。跨私有仓库 checkout 若缺少凭据，任务须明确失败或由已具权限的集成 workflow 承担，不能静默跳过并宣称兼容。

外壳比较使用与消费图一致的 ByteUI ref；CI 明确要求比较时，缺失源码必须失败。本地允许显式选择跳过。区域迁移完成后取消重复数据等值检查，改为 API 和计算样式验证。

### 3.4 外壳样式单一来源

ByteUI 持有共享顶栏、左右图标栏、状态栏、左右 zone、context menu、maximize overlay 及公共背景约定；具体集合以现有导出盘点为准，不能只根据“7/8 个区域”旧计数迁移。

Dozer 共享 accessor 委托 ByteUI，产品面板区域与 homespace 保留在应用。ByteHost 和 Digger 继续读取同一套共享定义。删除 Dozer JSON 中已迁移的重复键，修订旧拆库说明，退役相应比对脚本和 CI 步骤。

迁移前保存默认深浅方案、scale 0.5/1/2/3 的最终 background、border、padding、gap、margin 样本。迁移保持这些结果；发现已有差异时先记录并裁决目标，不能在去重中暗改外观。Dozer 启动加载 JSON 不得再覆盖共享 token 形成第二数据源；若发现产品有意覆盖，应以显式产品 override 表达并单独验收。

### 3.5 动画调度与计算

- 默认目标 30 FPS，按下一次期限请求重绘；普通鼠标/窗口事件导致的额外绘制不算调度违反，但不得形成新的立即重绘循环。
- 提供宿主控制的暂停/恢复参数；隐藏面板移出树或传入暂停态。最小化/失活策略由宿主传递，先核对现有窗口事件，不能假设 Canvas 知道可见性。
- 暂停时不自发续订；恢复后重建下一次期限，避免补画积压帧。时间语义采用暂停期间冻结曲线相位。
- 先测量，再决定采样缓存；有呼吸参数的曲线不能跨 detail 值错误复用。缓存有界，尺寸、颜色、曲线及相位变化按实际缓存内容失效。
- 记录同机同构建模式下 0/1/4 个动画、可见/隐藏/最小化的 CPU、实际重绘数与可取得的帧时间。定时调度不得因高刷屏自发提高到刷新率；测量噪声和工具不可用须如实记录。

### 3.6 主题一致性

先审计 Dozer 自定义 JSON 初始化、命名方案与任意 `set_theme` 的全部调用，再引入一个锁保护的 `ThemeSnapshot`，第一阶段包含 colors、scheme、revision。

- 每次有效主题变更原子替换快照并递增 revision；同一 snapshot 里的方案与颜色有一致来源。
- 命名方案提供明确的 Dark/Light。任意自定义 palette 不能伪称是内置配色；快照应区分来源与供网页/终端使用的明暗提示。旧 `current_scheme` 通过兼容明暗提示继续工作，不能为了统一快照擅自扩展旧 enum 导致所有 match 破坏。
- 原有 accessor 转发到快照；不在本轮强制迁移所有组件签名。font/geometry/icon size 的整体合并待需要时实施。
- setter 本身不声称能唤醒所有窗口。ByteHost/产品收到主题变更后，统一刷新已有原生窗口和第一方 WebView；新建/重载页面读取最新 snapshot。
- 网页主题投递使用同一 snapshot 生成方案与 CSS；对异步投递使用 revision 丢弃过期更新，页面重建时重新初始化。不得向第三方页面注入。
- 设置保存失败继续保留当前会话选择并显示可重试错误，维持 Digger 现有用户行为。

全局状态测试优先改为纯 snapshot 测试。必须修改全局值的测试使用同一进程范围内共享的串行设施与恢复 guard；模块各自建锁不能互斥，测试 panic 时也必须恢复。

### 3.7 可选 PanelHeading

盘点两产品和共享面板的标题组合，只有图标、标题、尾部操作及高度规则确实相同时才抽取。保留不同面板的布局差异，不扩张为业务面板框架。若无第二个真实消费场景，记录结论并跳过，不影响主线验收。

## 4. 验收矩阵

| ID | 场景 | 完成标准 |
| --- | --- | --- |
| BUI-01 | 缩放边界 | 所有入口不写入非有限或越界值；环境优先级、旧名、reset、初始化均有测试 |
| BUI-02 | 多窗口菜单 | 主窗/两浮窗切换、关闭、重开及迟到请求不串窗、不访问已销毁 view；所有菜单选择结果正确回传 |
| BUI-03 | 发布依赖 | 两产品 clean checkout 的 locked 构建通过，实际解析图及 ByteUI ref 留档 |
| BUI-04 | 候选兼容 | 精确 SHA 候选组合构建通过；故意不兼容候选可使门禁失败 |
| BUI-05 | 外壳去重 | 共享数据单一来源；深浅与四档 scale 的最终样式符合迁移基线 |
| BUI-06 | 动画 | 默认按 30 FPS 调度；暂停不续订；恢复无突跳；前后测量可复现，不夸大收益 |
| BUI-07 | 主题 | snapshot 一致；现存/新开/重载第一方页面均同步；过期投递不覆盖新主题；第三方页面不受影响 |
| BUI-08 | 标题抽取 | 两个真实消费场景迁移且布局不变，或明确记录跳过理由 |

## 5. 发布与回滚

先完成全部代码、测试、候选组合与变更说明，再准备新 tag 与消费方升级。保留现有默认外观、持久化格式及合法缩放行为。显式记录菜单 API 的破坏性变更，按仓库版本策略选择版本，不提前占用具体 tag。

依赖发布顺序为 ByteUI → 必需的 ByteHost → 必需的 Dozer 面板库快照 → 两产品。Digger 使用 Dozer 面板库，不能只升级应用而留下旧面板依赖图。按现有约定协调两产品同日升级。发布操作不属于本次文档任务。

各阶段独立提交。应用回滚恢复经验证的完整 tag/lockfile 组合；结构改造回滚需恢复相关 adapter、JSON 和脚本，禁止只回滚单个依赖号。
