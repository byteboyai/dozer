## 1. 现状与动机

现状 `view()` 是 `row![project, preview, terminal, ai]`——四栏固定同时可见。这个结构下有两个
具体的用户体验问题：

1. **右一"对话列表"点击后，审阅内容出现在左二"预览"栏**，中间隔着"终端"栏——两次点击之间
   视线要跨越整个窗口，且路径上还隔着一块无关内容（终端），容易迷航。
2. 与之对称的是：**左一"项目树"点击文件后，预览也在左二**——这条关系目前是对的（相邻），
   但四栏是固定顺序，没有办法让"项目树↔预览"和"对话列表↔审阅"两条关系同时都相邻——
   调整列序只是把问题从一条关系挪到另一条关系上（已在对话中验证：改成"项目|终端|预览|AI"
   顺序，会让"项目树点文件"也隔一条街）。

根本问题是**固定列序无法同时满足两条不同的"触发源→内容"邻接关系**。解法是不再用固定列，
改用图标栏驱动的模式切换：把强关联的"列表+内容"配对在一起，图标决定哪一对显示在哪一侧。

## 2. 整体外壳架构

窗口分四块：`[左图标栏][左面板区][右面板区][右图标栏]`——**没有第三块"始终显示"的中间区**。
文件预览、终端都不再是永远可见的常驻栏，而是各自挂在左/右图标栏的某个图标下，只有对应图标
被选中时才可见。

### 2.1 图标集（本轮固定，不做拖拽重排）

| 侧 | 图标 | 内容 | 形态 |
|---|---|---|---|
| 左 | 文件列表 | 项目树(列表) + 文件预览(内容) | 一对面板，可拖拽内部分隔线 |
| 左 | Web | Web 预览(地址栏打开的网页) | 单面板 |
| 右 | Agent | Agent 列表(列表,当前为占位) + 终端(内容) | 一对面板，可拖拽内部分隔线 |
| 右 | 对话 | 对话列表(列表) + 对话审阅(内容) | 一对面板，可拖拽内部分隔线——**本设计要解决的核心配对** |

**验收(Acceptance)不在图标栏里**：核对 Figma S2(`41:2`)后发现验收视图是独立的全屏接管
（自带"← 返回工作区"返回按钮、三栏内部布局：变更文件列表｜diff｜验收标准清单），不是挤进
侧边窄栏的内容。验收维持现状——由 S5 里"进入验收"按钮触发、"返回工作区"退出，完全不受本次
图标栏重设计影响。

**每个图标对应一个"视图"，视图的形态由内容本身决定，不强求统一**：文件列表/Agent/对话是
"列表+内容"配对，Web 是单面板——没有自然的"列表"对应物。

### 2.2 状态与交互细节

- **每侧当前激活的图标持久化**（扩展现有 `layout.json` 持久化机制），首次启动默认左=文件
  列表、右=Agent。
- **再次点击已激活的图标 = 收起该侧**（让出全部宽度给另一侧）——标准 activity-bar 交互
  （VS Code 同款），再点一次重新展开。
- **左右面板区之间的分隔线可拖拽**，与现有分隔线交互一致。
- **每个"配对"视图各自记住自己的内部列表:内容分割比例**（对话配对的比例 ≠ Agent 配对的
  比例），不共用一个全局比例——小的打磨点，避免一个视图的拖拽影响另一个视图的预期。
- 底部状态栏（项目栏底"环境正常"、终端栏底"思考中/Context"等）随各自面板挂到新位置，内容
  本身不变。

### 2.3 非目标（本轮明确排除）

- **图标可拖拽在左右栏之间自由重排**——用户提出但主动决定拆分到后续迭代。本轮架构不能
  堆死（图标→视图的映射独立于"在哪一侧"，为后续拖拽留门），但拖拽交互本身、持久化用户
  自定义排布，都不在本轮范围。
- 除下面 §3/§4 两项外，不引入新内容/新功能——这是对现有面板（项目树、文件/Web 预览、终端、
  对话列表、审阅、验收）的重新编排，不改变任何单个面板内部的行为。

## 3. 顶栏：项目页签取代搜索框 + 目标胶囊

参照 `design/参考/顶部项目tab参考.png`。顶栏从"Dozer 标题 + 全局搜索框 + 当前目标胶囊 +
设置齿轮"改为"Dozer 标题 + 项目页签条 + 设置齿轮"：

```
[红黄绿] Dozer  [项目1(active)] [项目2] [+]  ……  ⚙
```

- 每个页签代表一个项目，点击切换"当前活跃项目"。`+` 打开项目选择（复用现有
  `Message::ProjectPickFolder`/`ProjectSelect` 流程，只是入口从隐藏的"最近项目"列表变成
  顶栏常驻页签）。
- 全局搜索框（"搜索作品、会话、产物…⌘K"）与当前目标胶囊（"● 目标：…"，对应
  `.dozer/goal.md`）**本轮直接去掉**，不挪到别处。目标胶囊是验收闭环的入口 UI，去掉之后
  验收目标以什么形式呈现是待定项——见 §5。
- 设置齿轮位置不变。

### 3.1 待决议：项目页签背后的状态模型（重要，不是纯视觉问题）

页签暗示"多个项目可以同时打开、并排切换"，但现状 `Workspace` 同一时刻只持有一个
`project: Option<ProjectInfo>`，dozerd 侧 `set_active_project` 也是单一活跃项目语义。这里
有两种解法，本设计**推荐方案 A**，但这是一个需要用户确认的真实决议点，不是可以顺手定死的
细节：

- **方案 A（推荐）：页签是"最近项目"的快捷入口，不是并行工作区。** 点击页签 =
  现有的 `ProjectSelect`/`ProjectOpened` 流程（关旧项目的终端/预览 tab、开新项目的），只是
  从隐藏列表搬到了顶栏常驻展示。工程量小（复用现状态机），但代价是切换页签会让上一个项目
  的终端会话结束（同现状 `close_all_tabs_for_switch` 语义）。
- **方案 B：真正并行多项目**，每个页签背后是完全独立的一套状态（各自的文件树/终端/预览/
  对话），互不影响，切换页签只是切换"当前渲染哪一套"。工程量大得多——dozerd 需要支持多个
  项目同时"活跃"（当前协议是单一 `active_project`）、GUI 侧 `Workspace` 要么变成
  `Vec<Workspace>`要么抽出一层"项目态"容器。这已经超出"外壳重排"的范畴，是真正的新功能。

## 4. 每个内容 Pane 可放大到程序全屏

参照 `design/参考/放大pane.png`。每个内容类 pane（文件预览、对话审阅；同理应推广到 Web、
Agent 配对里的终端）的 tab 栏尾部加一个放大按钮（Lucide `maximize-2`）。点击后：

- 该 pane **以浮层形式**扩大到"两条图标栏之间"的整个内容区（不覆盖图标栏本身、不覆盖顶栏
  页签条）——是层叠(overlay)，不是布局重排。已验证效果见 Figma `106:30`。
- **背后其他内容保持渲染但变暗+背景虚化**（`BACKGROUND_BLUR` 效果 + 半透明黑色遮罩），
  不是直接隐藏——用户已确认采用这个而非"直接隐藏其他 pane"的方案，同参照图行为。
- 放大后的 pane 描边高亮（金色 `theme::GOLD`），与本仓"激活态用金色标记"的既有约定一致
  （激活项目页签、激活对话、激活图标栏图标都是这个视觉语言）。
- 再次点击放大按钮（或已放大 pane 上的等效"还原"控件）退出放大态，回到常态布局。

### 4.1 待决议：哪些 pane 有放大按钮

Figma 验证只做了"文件预览"和"对话审阅"两个。是否所有内容类 pane（含 Web、终端）都要有，
还是只有内容密度高、容易觉得"太窄"的那几个——本设计默认"所有内容类 pane 都有"（文件预览、
Web、终端、对话审阅），"列表类"（项目树、对话列表、Agent 列表）不需要，因为放大一个纯列表
没有实际意义。这个默认没有单独跟用户核对过，标记为待确认，不是已锁定决议。

## 5. 遗留的悬空项（不在本轮解决，明确列出防止被遗忘）

- **目标胶囊(`.dozer/goal.md` 验收目标)去哪**：本轮从顶栏直接移除，未指定新位置。用户
  当轮决定"这轮先不管，目标胶囊暂时去掉"——即这不是"决定不再需要这个功能"，只是"本次不
  设计它的新位置"，后续需要单独讨论（挂到项目页签上？挂到项目树 pane 顶部的项目卡片上？）。
- §3.1 的方案 A/B 决议。
- §4.1 的放大按钮覆盖范围。

## 6. 测试与实现方式说明（先写给后续 writing-plans 阶段看）

这是纯 UI 重排 + 交互，不引入新的领域逻辑分支，测试策略延续本仓既有约定：布局几何相关的纯
函数（新分隔线拖拽换算、放大态尺寸计算等）走单元测试，视图整体效果走"编译通过 + 真机目测"
——与本仓其余 view 层任务（上一会话的右键菜单、图标系统）一致，不引入新的测试哲学。
