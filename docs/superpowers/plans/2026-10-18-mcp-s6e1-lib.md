**Goal:** 让 `dozer-mcp` 变成两个产品共用的库:`run_main(product, features)` 取代写死的 `main`;服务器名、会话环境变量、socket、安装条目名、各 Agent 配置路径的环境变量覆盖名都取自 `ProductId`;工具按 `McpFeatures` 分组,未开启的**不出现在工具列表里**;新增「安静模式」(本产品会话变量缺失、但另一个已知产品的存在时,启动零工具服务而不是报错)。**Dozer 的行为字节不变。** 本轮只做 Dozer 侧,叠在 `feat/panel-agent-restore` 之上,不合并、不打 tag;Digger 升级钉版待验收后另行安排。不发布产品版本。

**Architecture:** 先在现状上写黄金测试(`tools/list`、`initialize` 应答、五种 Agent 配置的安装 / 卸载产物、`serve` 缺变量的报错文案),再改。`ProductId`(S6a 引入)补三个**推导方法**(不改构造函数签名):`mcp_bin()`、`env_prefix()`、`known_session_envs()`。`DozerMcpServer` 拿到 `features` 与一个可为空的 `session_id` 字段,改用 `#[tool_router]`(不带 `server_handler`)加手写 `impl ServerHandler`:构造时 `Self::tool_router()` 再按特性 `remove_route`,`list_tools` / `call_tool` 走这个路由,`get_info` 的服务器名由产品决定。`install` 的五个处理器多收一个「条目名」参数,默认产品下仍写 `dozer`;新增同名保护。

**Tech Stack:** Rust、`rmcp`(3.5.1,`ToolRouter::remove_route` 已存在)、`toml_edit`、`serde_json`、`dozer-core::paths::ProductId`。

**Spec:** `docs/superpowers/specs/2026-10-18-agent-mcp-s6e-design.md`(§2、§3 G1 / G3、§5、§6.1、§6.4 S6e-1、§7 Dozer 段、§8 D1–D4 与 Q1–Q3)。已批准的取舍:Q1 静默写全局配置(可卸载);Q2 同名条目保护(不覆盖用户手写的同名服务器);Q3 Digger 工具集比 Dozer 少。

## Global Constraints

- **前置:S6a 已在本分支的祖先里**(`ProductId`、`paths::install`、`paths::product()`、`dozer-hook` 的 `run_main` 模式随叠分支一起存在,**未合并 `main`**)。本计划开工时先 `grep -n "ProductId" crates/dozer-core/src/paths.rs` 确认存在;不存在就停下报告,不自己实现 S6a。
- **默认产品(`ProductId::dozer()`)下逐字节不变:** `tools/list` 的名称、描述、参数 schema;`initialize` 应答(服务器名、版本、能力声明);五种 Agent 配置的安装 / 卸载产物(含 Codex 的注释与无关表保留);`serve` 缺 `DOZER_SESSION_ID` 且没有任何别的产品变量时的报错文案与非零退出码。`dozer-mcp` 现有测试(`install.rs` 16 条、`tests/` 下 15 条)**原样通过、期望不改**,`serve_requires_session_id.rs` 不动。
- **安静模式的触发条件精确为:** 本产品会话变量**不存在** 且 另一个已知产品的会话变量**存在**。两者皆无 → 报错(同现状)。已知产品的会话变量名列表是 `dozer-core::paths` 里的一个常量(目前 `DOZER_SESSION_ID`、`DIGGER_SESSION_ID`),只含名字。
- **安静模式不连守护进程、不读 socket、不写 stderr,** 握手正常、`tools/list` 为空、stdin 关闭即 0 退出。
- **配置文件只增删自己名字的键;** 别的键(含另一个产品的)原样保留;读不出、解析失败、顶层不是对象 → 拒绝写入并返回非零(沿用现状)。Codex 继续用 `toml_edit` 格式保留编辑。
- **同名保护:** 目标键已存在且其命令(Claude 类的 `command`、Opencode 的 `command[0]`、Codex 的 `command`)**不含**产品名(大小写不敏感)时,不覆盖、返回错误码并说明;含产品名的(包括 Dozer 历史上写错成 `dozer-app` 路径的条目)照常覆盖——这条保证旧的错误条目仍能被「自愈」。这是个宽松匹配,已知局限:用户手写的、命令里碰巧含产品名的同名服务器会被当作我们自己的。
- 只用 git tag 依赖;Dozer 内部 `path = "../.."` 除外。**本轮不合并、不切 tag、不推送;** 这些只在用户一次性验收之后逐项确认再做。不发布产品版本(MCP 不是面板)。
- **主工作区别人未提交的改动不动;** worktree `../dozer-mcp-product`、分支 `feat/mcp-product`(从 `feat/panel-agent-restore` 顶端 `adae877b` 切出,见顶部修订)。
- 工具的参数、返回形状与描述文案不改;不新增 / 删除工具。

## Review Focus

1. **默认产品字节不变:** `tools/list`、`initialize`、五种配置产物、缺变量报错——任何一个逐字节有差异都算失败。→ Task 1、3、4。
2. **安静模式的边界:** 只有「他人变量在、自己的不在」才安静;空串变量值(`DIGGER_SESSION_ID=`)是否算存在(按「存在且非空」处理,与 hook 一致,先在现状上确认 hook 的判定);不连 socket(socket 不存在时也成功握手);stdin 关闭后 0 退出;不吐 stderr。→ Task 3。
3. **配置共存:** 先装 dozer 再装 digger、反过来、各自重复安装、各自卸载,三种格式(Claude 类 JSON、Codex TOML、Opencode)里另一个产品的条目始终字节不变;Codex 的注释、空行、键序、行内表父级保留;缺文件 / 空文件 / 损坏文件 / 非对象顶层。→ Task 4。
4. **同名保护与自愈:** 手写的同名条目(命令不含产品名)不被覆盖且返回非零;指向 `dozer-app` 的历史错误条目被覆盖修复;`command` 缺失、类型不对(数字、对象)、数组为空的条目——不 panic,按「不是我们的」处理并拒绝覆盖。→ Task 4。
5. **特性开关的完备性:** 每个特性组关闭时对应工具不在列表里、调用它得到「未知工具」而不是执行;全部开启时与 `McpFeatures::all()` 的黄金一致;`features` 全关等价于安静模式的工具集。→ Task 3。
