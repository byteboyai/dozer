## 1. 必须先纠正的错误

### 1.1 群聊成员 agent 在执行层是**只读**的(原稿 S8 §8 Q1 写反了)

原稿 S8 设计稿 §8 Q1 与 S8b、S8c 的约束写的是「群聊会拉起成员 Agent 命令行并让它们**在项目目录里工作**(与 Dozer 完全一致,不是只读聊天)」。**这与代码和 Dozer 的规定相反。** 读 `dozerd/src/group_adapter.rs` 得到的事实:

- Claude:`--allowedTools Read,Grep,Glob --disallowedTools Bash,Edit,Write,NotebookEdit,WebFetch,WebSearch`,加 `--no-session-persistence`。只能读和搜,不能写、不能执行、不能联网。
- Codex:`exec --ephemeral --sandbox read-only --skip-git-repo-check`。
- **严禁**加 `--dangerously-skip-permissions` / `-y`(Todo 任务处理里有,群聊不能抄)。Dozer 的 `CLAUDE.md` 把它列为「违反即错」。
- 子进程的工作目录是项目目录,所以成员**能读**项目文件,并会把读到的内容发给对应的模型服务;但**不能改**。
- 群聊只做讨论、**不分配任务**;`@` 只由人触发,agent 回复里的 `@` 不解析;webview 里 agent 输出必须经转义渲染器,不得 `innerHTML` 原文。

正确的措辞是:**用户发言时,后台以只读方式拉起被 @ 的成员,成员可以读项目文件作答,不能修改任何东西。** 对 S8 的影响:

- S8 设计稿 §8 Q1、S8b 头部「已批准的取舍:Q1…」、S8c Global Constraints 第 20 条、S8c Task 6 Step 2 ② 里「在项目目录里写文件的权限边界」的说法全部作废。S8c Task 6 Step 2 ② 的问题(要不要给 Digger 更严的默认)**取消**:Dozer 已经是只读,Digger 继承同一份 `dozerd` 代码,没有更严可加。
- 唯一仍然需要用户知情的是**隐私**:发言时项目文件内容可能被发给模型服务。这与用户在终端里直接用 agent 的性质相同,默认不加首次确认弹窗,但文案要如实(见 §5 Q5)。
- 只读不变式在后端**已有测试钉住**(见 §3.S8a);S8a 抽库期间不得删改。

### 1.2 只有 Claude 和 Codex 真能发言

`group_adapter` 对其它种类返回 `TurnError::Unsupported`(「该 agent 暂不支持群聊发言」),而 `CREATABLE_AGENTS` 里却有 Claude、Codex、Codebuddy、Opencode、Qodercn 五种。也就是说**能加进群、但发言时失败**的有三种。这是 Dozer 现状;S8 的「用户可见行为不变」据此,不改。要不要在 Digger 的新建群弹窗里提示或隐藏,见 §5 Q6。

### 1.3 已经解决的原稿未决项

- S8 设计稿 §9 与 S8a Task 1 Step 1 的「`env_remove("DOZER_SESSION_ID")` 是否已被 S6a 参数化」:**已解决**。`group_adapter.rs` 用的是 `dozer_core::paths::session_env()`(产品感知),Digger 的 `diggerd` 会移除 `DIGGER_SESSION_ID`。S8a Task 1 Step 1 改为「只读确认并在提交说明里记一句」,不再有「发现硬编码就最小改 `dozerd`」的分支。

## 3. 逐份修订

### 通用:所有 6 份计划都要加进 Global Constraints 的 S6 / S3b 教训

1. **`thread_local` 不得存订阅回调要读的状态。** `view()` 在主线程,订阅回调在 tokio 工作线程。S6d 里 `CURRENT_CURSOR` / `AGENT_KEYS_BLOCKED` 用 `thread_local` 导致 Agent 面板键盘输入整个失效,改用进程级原子才好。`thread_local` 只许存 wry 视图句柄,且只在 `window::run` 闭包里(主线程)访问。
2. **弹出菜单不得把下面的内容藏起来**(用户 2026-10-24 明确提出)。macOS 上凡下拉菜单一律用 `byteui::native_menu`(`show` / `install_content_view`,已随 byteui `v0.4.6` 共享,Digger 的 `adapters/native_menu.rs` 有转换样例),它浮在 wry 视图之上,**不需要隐藏 webview**。原稿里「任一覆盖层打开就隐藏 webview」只适用于 **iced 内的模态卡片和确认框**,不适用于菜单。原生菜单吞掉鼠标抬起,从它选中的动作要用「不武装拖拽」的变体(如 `SelectTabNoDrag`)。
3. **悬停与提示的控件树结构不能随 `show` 翻转。** 只在显示时才包 `Tooltip` 会重置子 `MouseArea` 的状态(重复 enter、丢 exit、计时器重置)。一律始终包 `Tooltip::delay`;进入事件要幂等(同槽重复进入不重置)。Digger 已有 `adapters/hover.rs` 的 `HoverTracker` 与 `TOOLTIP_DELAY`。
4. **Digger 没有 Toast。** 一次性失败落 stderr;持久状态(守护进程不可用)留在原位。需要面板内可见提示的,用 Agent 面板现有的通知条(S8b 抽成 `NoticeBar`)。不要为某个面板另造提示机制。
5. **webview 几何必须同源。** 原生子视图恒在 iced 之上;内容区下方、侧边若有 iced 控件(输入框、清空栏、面板头),webview 矩形必须用库导出的度量函数算,**不手写像素常数**,并加「不重叠」几何测试。
6. **协议与资源命名:每个面板自己的协议名** `digger-<面板>://`(已有 `digger-usage`,S3b 用 `digger-todo`),导航白名单只放行该前缀;嵌入资源在 `build.rs` 拷进 `OUT_DIR` 时加面板前缀,避免同名 `host.html` 互相覆盖。原稿写的「协议注册名取 `digger`、主机名 `review-trace` / `group-chat-content`」改为:S7 传 `scheme = "digger-review"`,S8 传 `scheme = "digger-groupchat"`(库的 URL 构造函数本来就带 `scheme` 参数,主机名仍由库决定)。
7. **服务束共用。** `UnavailableService` 与「只有一项真实、其余占位」的 `Services` 构造,S3b-1 Task 2 会把它从 `project.rs` 提成 `pub(crate)` 共用;S7b / S8b 的 `Daemon::*services()` 复用,不再各写一份。
8. **测试纪律**:验收测试在 `git archive` 导出的**干净快照**里跑(路径不含 "digger"),避免被 `.gitignore` 吞掉的文件造成假绿;偶发失败**单独重跑量化**(次数与失败数写进报告),不靠重跑到绿;`CARGO_TARGET_DIR` 不要与别的工作区共享(有集成测试硬编码了 `<worktree>/target/...` 下的示例二进制);Dozer 侧凡测试要改全局主题方案的,用 `theme::test_support::lock_scheme()`。
9. **提交纪律**:commit 前看 staged 全貌;不提交本地 `[patch]` 造成的 `Cargo.lock` 改动;提交信息末尾带 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`;**不碰用户主工作区的未提交改动,不碰 `feat/preview-pairing` / `digger-p4`**;不碰用户的沙箱 `/private/tmp/digger-sandbox` 与 `/Applications` 里正在运行的应用及其 `diggerd`。
10. **Dozer 侧门禁补充**:除原稿列的 `check-i18n.sh`、`check_panel_boundary.py` 外,加 `bash scripts/check-shared-deps.sh` 与 `bash scripts/check-log-scope.sh`(只有 `window_events.rs` 那处基线告警)。库内日志用 `tracing` 薄封装,不直接用 `dozer_core::log`(库不依赖 `dozer-core`)。

## 4. 发布的实际做法(S7c、S8c 的 Task 7 照此替换原稿的「发布」步骤)

本会话 2026-10-25 实际发 Dozer 0.5.306 与 Digger 0.1.6 时的流程,比原稿的描述更具体:

- **Dozer**:`bash scripts/build-macos-app.sh release` 自己会 `bump-version.sh` 升 patch;产物在 `target/aarch64-apple-darwin/bundle/macos/Dozer AI Coder.app`。提交版本号时,`Cargo.lock` **只提交 `dozer-app` 那一行版本号**(用户本地 `[patch]` 造成的其余改动留在工作区):用 `git show HEAD:Cargo.lock` 改那一行再 `git hash-object -w` + `git update-index --cacheinfo`,不要 `git add Cargo.lock`。
- **Digger**:`bash scripts/release.sh --allow-dirty`(工作区有用户未提交改动时必须带;它**不提交、不打 tag、不推送**,Digger 没有 remote)。门禁跑完全量测试约 7 分钟;**不要和 Dozer 的大编译同时跑**(会让 `apps::tests::closing_during_startup_waits_and_releases_the_root` 偶发失败,单独重跑稳定通过)。提交时只 `git add` 三个版本文件(`Cargo.lock`、`crates/desktop/Cargo.toml`、`crates/desktop/packaging/macos/Info.plist`)。
- **安装**:先把 `/Applications` 里的旧 `.app` **挪到备份位置**(不删),再 `ditto` 新包;`codesign --verify --deep --strict` 与 `CFBundleShortVersionString` 核对。**不要杀用户正在运行的应用与常驻 `dozerd` / `diggerd`**,告诉用户退出重开才生效。
- **推送 Dozer `main`** 可能触发它的自动发版流程;推送前先告知用户。
- **每一步对外动作(升版本提交、打 tag、推送、安装)都先问用户**;用户倾向把多处改动攒成一个版本一起发时,按用户的节奏来,不要每个面板迁移完成就自行发版。
