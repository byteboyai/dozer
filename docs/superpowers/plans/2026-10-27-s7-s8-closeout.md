### T3c 让 Codebuddy / Opencode / Qodercn 可在群聊发言(Dozer 后端,D3)

现状:`dozerd/src/group_adapter.rs` 只对 Claude、Codex 有无头只读调用,其余返回 `TurnError::Unsupported`。Digger 的 `diggerd` 继承同一份代码。

**硬约束(违反即错):** 群聊发言必须在**执行层**只读。每个新增 agent 都要找到并验证它自己的只读机制(工具白/黑名单或沙箱),**严禁**用 `--dangerously-skip-permissions`/`-y`/等价的「全放行」开关。**若某个 CLI 没有可在命令行层强制的只读模式,该 agent 保持 `Unsupported`,不为凑齐而放宽**,并把结论写进报告和弹窗说明。

- [ ] 逐个 agent 调研(读其 `--help` 与官方文档,实际在隔离目录里试跑):是否有无头一次性模式、能否禁写/禁执行/禁联网、是否会持久化会话(要求不落会话,类似 Claude 的 `--no-session-persistence`、Codex 的 `--ephemeral`)、输出怎么取、退出码语义。每个 agent 一张结论表,写进 `docs/superpowers/specs/` 下的调研记录。
- [ ] 对能做到执行层只读的 agent:先写失败测试(参数断言,仿现有 Claude/Codex 的钉住测试),再实现适配;并加一条**行为验证**:在临时目录里让它尝试写文件,确认被拒。
- [ ] 现有 Claude/Codex 的只读测试一条不许删改。
- [ ] 发言失败路径:未登录、命令不存在、超时,沿用现有 `TurnError` 的可见失败,不静默。
- [ ] `CREATABLE_AGENTS` 与「能否发言」两处保持一致;若有 agent 最终仍不支持,弹窗常驻说明改为列出实际不支持的种类,而不是删掉说明。
