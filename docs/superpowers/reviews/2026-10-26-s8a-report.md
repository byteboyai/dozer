## 与计划不一致 / 已知事项

1. **Task 2 与 Task 3 库侧合并提交**：为了让每个提交都可编译，库的协议/资源与状态/视图同提交；Dozer 宿主适配单独提交。
2. **`group_chat_webview_spec` 多一个 `theme` 参数**：计划接口只有 `scheme`，但当前 URL 的 `?theme=` 来自主题单例；库不依赖 byteui 主题时无法自行取值，产品传入显式 `theme`，URL 字节保持不变。
3. **`content_pane` / `list_pane` 返回库 `Message`**（不是泛型 `M`），由 Dozer 在调用点 `.map(Message::GroupChat)`；这是保留现有组装方式的最小改动。
4. **视图失败重试**：库 `ShellMessage::Retry` 仍存在；Dozer 的 webview 生命周期/重试清理由宿主保留。
5. **前端产物不一致**：见上，需用户决定是否在验收前单独刷新 `assets/group-chat-content`；本任务未提交新产物。
6. **`host_adapters/group_chat_panel.rs` 的 `list_collapse_button`** 当前返回空占位；现有群聊列表没有使用该按钮（折叠按钮由 Dozer 现有 view 代码保留），属于未用接缝。
