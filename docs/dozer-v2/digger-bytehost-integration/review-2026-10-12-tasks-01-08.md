## 发现

### R1 / P1：Usage 同帧销毁重建不会更换 Surface 身份

位置：`Z/crates/dozer-app/src/extensions/usage/surface.rs:71`；触发路径 `Z/crates/dozer-app/src/platform/window_events.rs:1044` 起的 `sync_previews`。

切换项目时 `sync_previews` 清空 WebView 池，随后在同一次调用中按新项目 desired 清单重新创建 Usage 固定槽。`take_usage_content_script` 之后看到的仍然是 `in_pool=true`，从未观察到 false，因此 `observe_instance` 不执行 Destroyed/rebuild，generation 不变，旧项目 WebView 在途 Ready 仍可通过 `accepts`。新原生实例也继承了旧实例 Ready/sent 状态，可能在握手前收到推送。

建议：在实际池删除/替换时同步通知 Surface，先失效旧身份，再生成新 spec、注册新原生实例。不能通过“下一帧有没有同一个数字 ID”推断实例身份。补项目 A→B 且两边 Usage 都可见的真实池集成测试，明确断言旧 Ready 被拒。

最小状态复现：对同一 UsageSurface 连续两次 observe_instance(true)，中间代表池完成 clear+recreate，旧 ID 仍被接受。复现使用真实 UsageSurface 源文件，仅替换其业务 payload 编码；实际池时序由生产代码确认，未运行真实 GUI。

### R2 / P1：替换物理槽只清路由，不清旧 Surface entry

位置：`B/crates/bytehost-desktop/src/surface/mod.rs:75`（register）、`:103`（apply）、unregister/drain_ready_pushes。

注册新 generation 时 router 会驱逐旧身份，但 `entries` 仍保留旧 Surface。后果有三类：旧 Ready entry 仍被 `drain_ready_pushes` 遍历并向新实例所在槽发送脚本；`apply(old_id, Ready)` 没有通过 router 校验，仍可能推进旧 entry；调用 `unregister(old_id)` 会按旧 entry 的 physical 值注销新实例路由。当前 Usage 每次 rebuild 也只 register、不 unregister，导致旧载荷和闭包随切换累计保留。

建议：让物理槽替换原子地清理路由与 entry；注销必须核对当前占有者；所有事件和脚本枚举仅面向当前注册身份。补“旧实例已 Ready 后替换”与“迟到清理旧 ID”用例，而不是只测试从未注册的旧 ID。

两项复现失败：旧 Ready 实例替换后仍产生 push；注销旧 ID 后新 route 丢失。

### R3 / P1：run_scoped 校验发生在后台入队前，不是 UI 消费时

位置：`B/crates/bytehost-core/src/request.rs:246`。

work 完成后调用 tracker.accepts，然后 emitter 将结果入队。若结果已入队、UI 尚未消费期间同 key 发起新请求，旧 envelope 仍可交给消费者。desktop 当前也没有使用“当前存活 tracker”进行二次校验的共享消费入口。闭包 clone 的旧 tracker 同样无法知道产品已销毁并替换实例。源码注释与 ledger 中“已入队结果也能被拒”的承诺不成立。

建议：后台只执行并封装结果，在 UI 派发到 Product 更新之前，以当前 scope/instance 的 tracker 校验；保留 scoped write 执行完整性。测试必须让第一次结果先入真实消息队列，再 begin 第二次请求，最后消费；当前测试多数在 work 执行前就使 token 失效，未覆盖该窗口。

复现：先 run_scoped 成功入队，再 begin 同 key，接收端仍收到旧 envelope。Dozer 自己的 AsyncResult 接收路径仍有额外 accepts，本条不是断言所有 Dozer 面板已经回归，而是公共执行层尚未兑现所声明的契约。

### R4 / P2：隐藏恢复绕过 Ready 握手

位置：`B/crates/bytehost-core/src/surface.rs:287`。

WaitingReady 可以进入 Hidden，Hidden 恢复却无条件进入 Ready。Created→Hidden→Resumed、尚未收到一次 Ready 时，take_pending 已返回 payload；宿主页处理函数尚未安装时可能丢掉首帧。Hidden 下收到 Ready 又直接忽略，状态没有保存是否已握手，无法区分两种情况。

建议：分别维护 visibility 和 readiness，或保存 Hidden 前状态及隐藏期间握手结果。补“未 ready 即隐藏恢复”与“隐藏期间收到 ready”两条测试。前一条已复现失败。

### R5 / P2：注册目录拒绝没有 WebView 的原生面板

位置：`B/crates/bytehost-core/src/registry.rs:79`。

PanelCatalog::register 对 surfaces 为空直接返回 NoSurfaces。Surface 在本规格中是可选 WebView 承载机制；Digger 大纲、状态页和文件树等纯 iced 面板不应被迫声明虚假 WebView。此约束并非重复 ID 校验的要求，会阻止正式壳按产品清单注册原生面板。

建议：允许零 Surface，仅对存在的槽位进行合法性/重复检查；把当前断言“无 Surface 应失败”的测试改为原生面板可注册。最小复现失败。

### R6 / P2：合法 AppId 无法映射为 PanelId

位置：`B/crates/bytehost-core/src/id.rs:56`；对照 `B/crates/bytehost-apps/src/id.rs` 的 AppId::new。

AppId 允许数字开头（如 `123-notes`），PanelId 的每一段却要求小写字母开头，因而 `app:123-notes` 被拒。既有合法安装应用在接入 rail/注册表时无法表示；for_app 同样经过 new，不能绕开。

建议：对 app 命名空间与已校验 AppId 的形状保持兼容，同时保持普通产品命名空间的规则。增加边界映射样例，不能只用 excalidraw 一种字母开头 ID。最小复现失败。

### R7 / P2：Task 02 的 SELFTEST 跳过 WebView 构建，验收证据不足

SELFTEST 模式创建了 build Task，但返回 Task::done(Quit)，没有返回/执行 build。该命令 exit 0 只能证明 iced 窗口入口可启动，不能证明 wry 子视图构建成功，更不证明 resize、隐藏恢复、原生浮层等 Task 02 退出条件。Task 03 ledger 也只记录只读调查，没有计划要求的隔离双启动/退出实验；Task 08 ledger 已明确保留真实窗口人工确认，状态为 IN_PROGRESS。

建议：SELFTEST 必须等待 HostBuilt(Ok) 后执行生命周期验证，再退出；失败时非零返回。补真实窗口证据与 Task 03 服务实验，并据实修订 Task 状态。在此之前不能概括为 Task 01–08 已全部完成。
