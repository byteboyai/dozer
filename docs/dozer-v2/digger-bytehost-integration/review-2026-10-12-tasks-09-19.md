## 1. [P1] 请求序号被重用，迟到回包可冒充新请求

位置：`digger/crates/app-host/src/request.rs:92-95,124-125`。

`dispatch` 从当前 live 项计算 sequence，`accept` 成功后删除该项。因此 A(seq=0) → B(seq=1) → 接收 B → C(seq=0) 后，迟到的 A 会通过身份检查，并消费 C 的登记。列表、日志或 launch URL 会应用过期结果，同时丢弃真正的最新结果。

应使用不随 pending 记录删除而重置的请求身份；增加上述三请求乱序测试。此次从生产文件提取的 RequestTable 在该测试中失败。

## 2. [P1] 一次性写动作仍被 latest-only 覆盖

位置：`digger/crates/app-host/src/request.rs:96`；`digger/crates/app-host/src/effects.rs:407-411`。

`RequestKey::latest_only()` 声明 Action 不去重，但 dispatch 无条件覆盖 `(panel,key)`。Stop/Uninstall/Rollback 又各自对所有应用使用相同常量 key。连续停止两个应用时，两次后台操作都会执行，但先发动作的结果被拒收，相关 UI 无法收到成功或错误。`desktop/src/apps/mod.rs:293-301` 确实按 accept 结果丢弃回包。

应让每个写动作有独立在途身份，同时保留读取请求的 latest-only 语义。此次双 Action 回包测试失败。

## 3. [P1] 退出超时会在旧服务仍活着时释放独占锁

位置：`bytehost/crates/bytehost-apps/src/service.rs:456-470`。

timeout 分支释放 service lock 并直接返回，未执行下方的 gateway.stop。超时的 spawn_blocking 任务不会随 JoinHandle 丢弃而取消，可能仍在运行 suspend_all。此时新服务可以取得同根锁，却碰到旧 gateway 占用端口；若使用其他端口启动，还可能与旧 manager 并发操作同一数据根。

应保证 gateway、后台收尾和锁的生命周期一致；超时报告不能提前放弃独占权。另需将 runtime cancel/join 纳入总退出时限，否则当前 timeout 不约束前面的等待。本项由代码路径确认，未运行真实进程故障注入。

## 4. [P1] 高版本布局加载失败后，退出会覆盖原文件

位置：`digger/crates/desktop/src/product.rs:163-174,109-111,223-225`。

migrate 和 Layout::load 的 UnsupportedNewerVersion 都被吞掉，随后用默认布局启动；正常退出无条件 save，覆盖原高版本文件。备份文件不能代替“拒绝覆盖”契约，尤其备份只创建一次。

应保留不可写的加载状态，允许内存默认显示，但禁止保存到不支持的原文件。此次使用 schema_version=999 的文件复现退出保存，文件被改写为 schema 1 默认布局。

## 5. [P2] 稳定布局每次仍走历史迁移，丢失宽度和保留项

位置：`digger/crates/desktop/src/product.rs:163-165`；`bytehost/crates/bytehost-desktop/src/layout.rs:95-122`。

当前 schema 文件也先送进 legacy adapter；迁移只读取 items，所有宽度重建为 280，retained_unknown 重建为空，后面的稳定 schema load 不会执行。此次保存宽度 420 后加载得到 280。当前产品尚未渲染分栏，但已经执行布局读写，持久化数据会被修改。

应先识别稳定格式并走 Layout::load，仅对真正历史格式执行迁移，覆盖宽度及未知 ID 的 round-trip 测试。

## 6. [P2] Surface 生命周期接线形成无限递归

位置：`digger/crates/desktop/src/product.rs:269-273`；`bytehost/crates/bytehost-desktop/src/shell.rs:104-116`。

Product::update 收到 Surface 后调用 update_surface，后者调用 route_lifecycle；route_lifecycle 又调用同一 Product::update(Surface)。任何进入这条路径的 Surface 事件都会递归至栈溢出。目前真实视口尚未挂载，因此是接线启用即触发的潜在崩溃，不能把本次表格测试视为生命周期接线验证。

应由外层单次调用 route_lifecycle，产品消息处理函数消费事件，避免重新分发给自身。补一个使用真实 ProductShell 的事件路由测试。
